1. 📐 Generator Architecture Overview

Purpose

The generator subsystem provides flexible input generation strategies for testing math functions across different value ranges and distributions. All generators implement the IGenerator<T> interface for polymorphic usage.

🔑 Key Design Principles

  • Interface-based: All generators implement IGenerator(T) for uniform access
  • Type-parameterized: Support float, double, and SIMD types
  • Factory pattern: MultiStepGenerator creates appropriate concrete generator
  • Iterator-like: next() and has_next() methods for sequential access
  • Batch support: wrap_next(n) generates multiple values efficiently

  • Distribution: Uniform linear spacing
  • Formula: value[i] = start + (stop - start) * i / (count - 1)

💡 Best Practices

  • Linear: Default choice for most accuracy testing scenarios
  • Exponential: Use when testing over many orders of magnitude (e.g., 10^-38 to 10^38)
  • Bit-step: Use sparingly with narrow ranges, excellent for finding edge cases
  • Random: Complement deterministic testing, use fixed seed for reproducibility
  • Integer: Essential for functions like pow(x, n), ldexp(x, exp)
  • Fixed: Performance testing baseline, special value validation (NaN, Inf)
  • Combine multiple: Use different generators in separate test sets for comprehensive coverage
