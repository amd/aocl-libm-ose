1. 📐 YAML Parser Architecture Overview

Purpose

2. 📋 YAML File Structure

Overview

Test configuration files follow a hierarchical structure with three levels: test sequences, test sets, and individual tests. This organization allows logical grouping and efficient test management.

# Top Level: Array of test sequences - test_sequence: "accuracy_tests" function: "sin" test_sets: # Second Level: Array of test sets - id: "basic_range" description: "Basic range testing for sin function" tests: # Third Level: Array of individual tests - id: "accu_sin_range_01" input: - ["0.0", "6.28318530718"] # Range: [start, stop] type: - "linear" steps: - "10000" variants: - "ss" - "sd" - "vrs4" uth: - "0.5" - "0.5" - "4.0"

🔑 Input Types

  • Single Value: Scalar YAML node → stored in param.input[] as string
  • Range: Sequence [start, stop] → stored in param.range[] as InputRange structure
  • Multiple Ranges: Can have multiple ranges for multi-parameter functions (e.g., pow(x, y))
  • Type Specification: Each range has associated type (linear, expstep, bitstep, random, etc.)
  • Step Count: Number of values to generate in range (default: 1000)

🔑 ULP Threshold Rules

  • Scalar Variants (ss, sd): Default ULP = 0.5 (very strict accuracy)
  • Vector Variants (vrs4, vrd2, etc.): Default ULP = 4.0 (relaxed for SIMD)
  • Custom Override: Can specify per-variant thresholds via 'uth' array
  • Empty ULP Value: Falls back to default based on variant type
  • Format: Semicolon-separated string (e.g., "0.5;0.5;4.0;4.0")
  • Alignment: Must have same count as variants array
