Note: aocl-libm build should be done.

1. Create and navigate to the build directory:
    ```sh
    mkdir build && cd build
    ```

2. Configure CMake for `libm_almbench`:
    ```sh
    cmake .. -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=g++ -DALM_DEPS=ON
    ```
    - `-DCMAKE_BUILD_TYPE=Debug` : to build the almbench in debug mode
    - `-DCMAKE_BUILD_TYPE=Release` : to build the almbench in release mode
    - `-DCMAKE_CXX_COMPILER=g++` : select C++ compiler (g++ or clang++)
    - `-DALM_DEPS=ON` : build dependent libraries (amd, mkl, gcc, and YAML Libraries)
    - `-DALM_DEPS=OFF` : default (disable dependent builds)

3. Build `libm_almbench`:
    ```sh
    cmake --build . --config Debug
    ```

4. Run the executable:

    **For AMD:**
    ```sh
    export LD_LIBRARY_PATH=/path/to/amd_library:$LD_LIBRARY_PATH
    ```
    - Run your application:
      ```sh
      ./libm_almbench ../libs/libshimamd.so ../config/generic.yml
      ```
    **For GCC:**
    - Run your application:
      ```sh
      ./libm_almbench ../libs/libshimgcc.so ../config/generic.yml
      ```

    **For MKL:**
      ```sh
    - If MKL libraries are not found, manually update `LD_LIBRARY_PATH`:
      export LD_LIBRARY_PATH=path_to_mkl/lib:$LD_LIBRARY_PATH

      ```
    - Run your application:
      ```sh
      ./libm_almbench ../libs/libshimmkl.so ../config/generic.yml
      ```


#Steps to Build and Run on Windows

## Prerequisites
1. Install Visual Studio 2022 with C++ development tools
2. Install LLVM/Clang
3. Install CMake and Ninja
4. Install MPFR dependencies at C:\drives\mpfr

## Build Steps

1. Open Windows PowerShell as Administrator and set up the Visual Studio environment:
   # Initialize Visual Studio environment
   ```
   "path_to_msvc\Community\VC\Auxiliary\Build\vcvars64.bat" x64
   ```

2. Verify tool versions:
   ninja --version
   cmake --version
   clang --version
   ```

3. Set environment paths in PowerShell:
   ```
   set REF_MPFR="mpfr_path\mpfr"
   set PATH=path_to_aocl_libm\build\dev-win-release-llvm\lib;%PATH%
   set PATH=mpfr_path\mpfr\mpfr_x64-windows\bin;mpfr_path\mpfr\gmp_x64-windows\bin;mpfr_path\mpfr\mpc_x64-windows\bin;%PATH%
   ```

4. Create and navigate to build directory:
   ```
   mkdir build && cd build
   ```

5. Configure with CMake:
   # For standard build
   ```
   cmake .. -G Ninja -DCMAKE_BUILD_TYPE=Debug -DALM_DEPS=ON -DCMAKE_C_COMPILER="C:/Program Files/LLVM/bin/clang.exe" -DCMAKE_CXX_COMPILER="C:/Program Files/LLVM/bin/clang++.exe"
   ```

6. Build the project:
   ```
   cmake --build . --config Debug
   ```

7. Run test cases:
   # Test with AMD shim
   ```
   .\libm_almbench.exe ..\libs\libshimamd.dll ..\config\generic.yml
   ```

   # Test with MKL shim
   - Update `PATH`:
      ```sh
      set PATH=path_to_mkl\bin;%PATH%
   ```
   .\libm_almbench.exe ..\libs\libshimmkl.dll ..\config\generic.yml
   ```

## Troubleshooting
- On Linux and Windows respective paths(LD_LIBRARY_PATH or PATH) should be set before starting testing.
- If you encounter “DLL\SO not found” errors:
      - Verify that all required binaries are present in the set path.
      - Confirm that the respective environment variable is correctly configured.
- Check that MPFR dependencies are properly installed at mpfr_path

Note:
1. For GCC, sincos has a known glibc bug. The vector variants have issues, so we currently fallback to scalar implementation.
2. cexp is not implemented yet.
3. On windows ldexp is not supported for MKL.
4. If all APIs accuracy need to be tested, a single generic.yml can be used.
5. For individual API testing, corresponding YAML files are available under: almbench/config/
6. For all APIs UT/VT/PERF (lower case also supports) master_tests_all.yml file can be used.
