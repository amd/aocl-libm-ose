🔑 Key Components

  • Input Layer: YAML configurations define test specifications; CLI provides runtime parameters
  • Core Engine: Parses configurations, dispatches tests to appropriate handlers, manages libraries
  • Execution Layer: Separates Unit Test (direct validation) and Range Test (input generation) execution paths
  • Validation Layer: Compares against reference implementation, computes ULP errors, measures performance
  • Output Layer: Serializes results to YAML format with detailed metrics and diagnostics
  • External Libraries: Shim library (function under test) and reference library (high-precision ground truth)

🔑 Workflow Stages

  • Initialization (Phase 1): Load libraries, validate environment, prepare execution context
  • Configuration (Phase 2): Parse YAML test specifications, extract metadata, prepare test matrix
  • Test Generation (Phase 3): Split into variants, create type-specific contexts, route to handlers
  • Execution (Phase 4): Three modes - Unit (single value), Accuracy (batch validation), Performance (timing)
  • Verification (Phase 5): Compare results, compute ULP errors, check thresholds, determine status
  • Reporting (Phase 6): Serialize to YAML, generate statistics, write output files
  • Cleanup (Phase 7): Release resources, finalize reports, graceful shutdown

🔑 Coverage Highlights

  • Scalar Coverage: Tests standard C APIs for float and double precision operations
  • SIMD Coverage: Validates SSE (128-bit), AVX (256-bit), and AVX-512 (512-bit) vectorized implementations
  • Array/Batch Coverage: Tests pointer-based batch APIs for high-throughput scenarios
  • Architecture Detection: Automatically skips AVX-512 tests on unsupported hardware
  • Validation Types: Accuracy (ULP errors), Performance (timing), Exceptions (error handling), Special values (edge cases)
  • Comprehensive Testing: Each math function tested across ~10 variants ensuring complete platform coverage
  • Quality Metrics: Scalar ULP threshold 0.5, Vector ULP threshold 4.0, Performance comparison across variants

📌 Executive Summary

The AMD LibM Test Suite provides comprehensive validation of mathematical library functions across multiple dimensions:

  • Multi-Architecture: Tests scalar, SSE, AVX, and AVX-512 implementations
  • Multi-Precision: Validates both single (32-bit) and double (64-bit) precision
  • Multi-Mode: Supports unit testing, accuracy validation, and performance benchmarking
  • YAML-Driven: Flexible configuration system for test specification and extensibility
  • Reference Validation: Uses high-precision MPARITH/MPFR libraries for ground truth
  • ULP Accuracy: Rigorous error measurement with configurable thresholds
  • Cross-Platform: Supports Windows and Linux with platform-specific optimizations

Result: Production-ready math library with verified correctness and performance across all target platforms and architectures.
